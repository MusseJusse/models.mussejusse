Model catalog redesigns, five directions

The current catalog is a 10-column data grid. On desktop it works. On a phone the grid keeps its 1,535px fixed width and the user pans sideways through a forest of borders. These mocks fix that and tighten the desktop UI along the way.

Every direction shows the same five sample rows in a desktop frame and a mobile frame. Sample data mirrors the real catalog: model, provider, context limit, input and output price per 1M tokens, capabilities, weights.

ACards on mobile, table on desktop

The direct fix. Desktop keeps a table but drops the vertical cell borders, which is most of the visual noise. Below 720px the same data reflows into cards: name and ID on top, a three-column stat grid, capability pills at the bottom. No horizontal scrolling anywhere.

  • Cost per 1M moves next to the model name on mobile because price is the second thing people scan after the name.
  • Capability icons keep their tooltips; on touch they become a legend row under the filter chips.
  • Cheapest change to ship: one CSS container query and a second row layout, no new components.

BKeep the table, cut the columns

For people who want a table on mobile too. The fixed 10-column grid becomes a two-zone layout: the model column stays pinned to the left while the value columns scroll under it. On phones the grid drops to the four columns that carry decisions: model, context, input, output. Release date, updated, and capabilities move to the detail view.

  • Two-zone scroll: name column sticky with a hard right edge and shadow, value columns pan under it.
  • Row height drops to 44px on mobile so five rows fit where two fit today.
  • Model ID and copy button live in the row detail, not in the grid. IDs are for machines; the name is for people.

CBottom sheet filters

The provider picker is the worst mobile offender: a dropdown anchored to a 56px header, holding 43 checkboxes in a 360px menu. This direction collapses all filters into one pill row and opens them in a bottom sheet with a segmented release control, provider checkboxes, and a sticky apply button. The sheet is swipe-to-dismissable with momentum.

  • The apply button states the result count, so users see the effect before committing.
  • Release ranges become a segmented control. Six radio rows become one glanceable row.
  • Desktop keeps the current dropdown pickers. Only mobile gets the sheet.

DSearch-first, keyboard led

Most sessions here start with a model name in mind. This direction makes search the page: a large query field, results grouped by provider, and filters as a single sort chip. Mobile gets a full-screen search view with the on-screen keyboard accounted for: results start at the top of the viewport and the list thins to essentials.

  • Provider grouping replaces the provider column. Repetition becomes structure.
  • Context and both prices sit on one line per row, right aligned. Two numbers per row instead of six.
  • Existing keyboard shortcuts already support this: / and Cmd+K focus search today.

EDetail panel and expandable rows

The table hides the data people actually need to decide: modality support, output limits, exact IDs. This direction moves depth into a detail surface. Desktop shows a right-hand panel for the selected model. Mobile expands the row in place, an accordion with the same content. The grid itself gets shorter and quieter because it no longer carries everything.

  • Expanding a row keeps scroll position and context. Nothing covers the list.
  • The copy-ID button finally has a home that works on touch, where hover-reveal buttons are unreachable today.
  • The output-vs-context bar shows how much of the window the model can actually write.

All five directions share one base move: the 1,535px fixed grid stops being the only layout. A and B differ in how much of the table survives on phones. C fixes filtering. D reorders the page around search. E adds the detail layer the grid never had. They combine cleanly: A's mobile cards plus C's bottom sheet plus E's expansion is one coherent build.
